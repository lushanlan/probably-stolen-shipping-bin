# 游戏内验收清单（尚未执行）

使用独立测试档，记录游戏版本、模组 DLL 哈希、初始现金、恩惠、声望和物品。每个失败情况都应记录游戏界面、日志和重新读档后的结果。

## 购买与赠送

  默认买店前入口隐藏；开启提前购买后出现，关闭后再次隐藏。买店后正常显示。
  现金充足、恩惠充足、两者混合支付分别购买，检查各自扣款；同日重复不可买，睡觉后次日可买。
  装满可接收位置后尝试购买，确认现金、恩惠、每日冷却和购买统计没有变化，也没有丢失或重复箱子；腾出空间后再次购买成功。对预检通过但实际放置失败的异常路径做受控测试。
  调试模式默认关闭；开启后新局只赠一次。空间不足时保留待领取状态，腾出空间后可恢复；反复读档不重复赠送。旧档打开调试模式不补发，赠送不改变购买解锁。

## 升级与保存

  两个箱独立累计垃圾、废金属、金属锭，逐项确认每次增加 1、2、5 点和原版 Tinkerer 触发时免耗仍加点；确认材料原有其他用途不受影响。
  跨越各阈值后分别核对格子数量和余点，满级拒绝继续投入；最后一笔溢出须明确提示。不同组合达到相同累计点数应得到相同容量。
  每档放入物品后保存、退出并重新读档，核对箱子、内容、容量与累计点数；验证最大窗口能完整显示、操作和保存。价格、阈值和尺寸以最终确认文档为准。

## 销售与保护

  多箱、箱中箱及装有普通容器的货物只计一次，任意后代含任务物、非玩家所有或禁售物时整个待售根物保留；出货箱自身不会被出售。
  对赃物、违禁品开关分别验证；黑市声望 99、100、199、200 在减半与豁免开关组合下逐项核算。混合假标签货物同晚合计扣声望，验证零收入仍有最低处罚、四舍五入及 20 上限。
  验证睡前快照、晚间结算日志、总收益、犯罪记录及再次读档不重复。中途异常、满现金范围和无空间情形不得吞物或重复发钱。

## 调试赠送与正常购买并存（本轮修复点）

  先正常购买一个出货箱（该箱没有赠送 token），再开启调试模式并开新局；确认新局仍会赠送，且不会把正常购买的箱子当成"已赠送"。
  若上一局因空间不足留下待领取状态（`debug_grant_pending`），在本局腾出空间或正常购买后读档/睡觉，确认补领仍会发生、且补领成功后不会再次赠送（`debug_grant_done`）。
  关闭调试开关后再打开，确认不改变每局一次的语义（未领取的待补状态保留）。

## 结算失败语义（能实机验证的部分）

  正常夜间结算：日志应包含出售件数/收入/保留件数及原因/涉案/假贴标扣声望。
  在同一晚再次睡觉（或读档回睡前）：不得重复付款、不得吞掉保留物；已售货物不应回到箱内。
  失败/回滚路径（部分取下、付款中途失败、销毁失败、涉案或假贴标提交异常、写结算标记失败）无法在实机可靠复现，由 `tests\CoreTests.cs` 的 `FakeWorld` 故障注入覆盖；实机只需确认出现异常时夜间日志会明确说明"部分记账/已回滚/回滚未确认/未写结算标记"，而不是静默成功。
